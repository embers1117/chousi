# 抽丝 · 设计提纲

> 这份文档是先于代码写下的提纲，后面又按实际实现校正过。目的是把「为什么这么拆」讲清楚，
> 而不是复述代码。想直接跑起来看 [README](../README.md)。

---

## 1. 要解决的问题

**一句话**：用户手上有一大段非结构化文本，需要变成一条条可执行的待办。

典型输入：

- 部门/学校群里的**通知**（一屏文字，时间地点人物混在一句里）
- **会议纪要**、邮件（多条行动项散落在段落里）
- 自己随手记的**一大段备忘**

典型痛点：普通待办 App 只提供空输入框，用户要做的是「人肉信息抽取」——
这段里有哪些事？几点？在哪？要带什么？谁负责？**抽丝把这一步自动化。**

### 不做的事（边界）

- 不做账号与多人协作（至少第一版）
- 不做完整的任务管理（甘特图、子任务、依赖关系）
- 不追求 100% 准确：**允许抽出可编辑的草稿**，比"看起来准但改不了"更有用

## 2. 关键设计判断

| 决策 | 选择 | 理由 |
|---|---|---|
| 形态 | 纯静态单页 | 双击即开、可离线、可挂 GitHub Pages、零运维 |
| 抽取方式 | 规则引擎为主，LLM 可选 | 不填 Key 也能用；隐私默认不离开本机；离线可用 |
| 技术栈 | 原生 HTML/CSS/ESM，**零依赖** | 十年后还能跑；没有构建链腐烂问题 |
| 时间表示 | 存本地墙钟时间 `YYYY-MM-DDTHH:mm` | 直接喂 `<input type="datetime-local">`；用户关心的是"明天9点"而不是 UTC |
| 结果可信度 | 每条都带**置信度**和**原文出处高亮** | 让用户能快速核对，而不是盲信 |
| 抽取粒度 | 一句一事件（事件单元） | 长文里通常"一个时间锚点 = 一件事" |

## 3. 抽取流水线

```
原文
 ├─① 归一化 normalize      全角数字→半角、全角空格→空格；**逐字符 1:1 替换**，保证偏移不变
 ├─② 切行 splitBlocks      按行切；行首的 1. / ①/ - 等列表符号剥掉
 ├─③ 切句 splitClauses     按 ，。；！？、 切；冒号只在非数字之间切（保护 9:30）
 ├─④ 归类                 每句判成：表单属性行 / 任务句 / 续写句 / 过渡词
 ├─⑤ 聚合成事件 segment    属性与续写只会被挂到所属事件，不会自成一条
 ├─⑥ 认时间 findTimes      词法扫 token → 语法合并 日期+时段+时刻 → 解析成 Date
 ├─⑦ 填字段 buildItem      标题（选句+剪裁）、地点、人物、备注、优先级、分类、置信度
 ├─⑧ 合并去重 mergeItems   同时间 + 标题相似 → 合并备注
 └─⑨ 排序                  有时间的按时间升序，没时间的按置信度
```

### ④⑤ 分段：为什么不能「一句一待办」

第一版就是「含时间锚点的分句 = 一件待办」，结果一塌糊涂：

| 输入 | 第一版产物 | 问题 |
|---|---|---|
| `明天下午3点开会，4点半结束` | 「开会」+「结束」两条 | 一件事被拆成两条，且「结束」被解析成凌晨 4:30 |
| `地点：三楼会议室`（单独一行） | 一条叫「地点」的待办 | 属性被当成任务 |
| `明天9点面试` / `请携带身份证` | 「面试」+「携带身份证…」两条 | 备注被当成任务 |
| `2点签到，3点开始，5点结束` | 三条 | 同一天的一次活动被切成三段 |

第二版改成**先归类、再聚合**：

- **表单属性行**（`时间/地点/内容/备注/联系人/议程：值`，支持一行多组）→ 永远挂到当前事件；
  其中 `内容/主题/议题` 直接当标题，`会议时间` 这种键还会兜底出「会议」这个标题
- **续写句**（去时间后只剩 `结束/散会/签到/出发/集合/开始…` 且 ≤14 字）→ 挂到当前事件：
  `…结束` 记进结束时间，其余进备注（`3点正式开始`）
- **过渡词**（`另外/还有/最后提醒一下`）→ 直接丢弃
- **只有「含时间 且 是任务句」才开新事件**；跨行时以 `请/记得/携带/务必…` 开头视为续写
- **抬头句**（`【部门通知】各位同事`）不单独成条，被下一个事件吸收
- 收尾还有两道闸：2 字且无动词的标题（`王总`、`地点`）直接丢弃；纯地点标题（`三楼会议室`）不算标题

### ⑥ 时间解析：两阶段

**词法**：用一组正则扫出 token，再按「起点早、长度长」贪心去重叠。覆盖：

- 绝对日期 `2025年5月3日` / `5月3日` / `5-3` / `15号`（无月份时按"已过就下个月"推）
- 相对日 `今天 / 明天 / 后天 / 大后天 / 昨天`，周期词 `下周 / 月底 / 今年年底 / 下旬`
- 星期 `周三 / 下周五 / 下下周三 / 周末`（裸"周五"在周三说 = 本周五；在周六说 = 下周五）
- 时刻 `9:30 / 3点半 / 三点一刻 / 下午两点`，时段词 `上午 / 中午 / 晚上 / 凌晨` 参与 12→24 换算
- 区间 `9:00-11:00 / 晚上7点半到9点`
- 相对时长 `三天内 / 一周后 / 半小时后`
- 模糊词 `尽快 / 待定`（不硬塞日期，只标记"表述模糊"）

**语法**：把相邻 token 合成一个完整时间点（`下周三` + `下午` + `3点` → 5/14 15:00），
并识别截止语义：后面跟 `前 / 之前 / 以前`，或前面有 `截止 / 截至 / DDL`。

**反例防护**：`3-5人`、`1-2天`、`500-800元`、`http://` 不能被误判成日期/时刻——
靠前置字符、后置量词黑名单和数值范围三重校验。

### ⑦ 标题：从原文里"剪"，不是生成

规则引擎不做自然语言生成，而是**挑选 + 剪裁**：

1. 给每个分句打分：含动作动词 +4、含主时间锚点 +5、带"请/需要" +1.5、
   以"务必/准时/提前"这类修饰语开头 −2.5、纯过渡语（"另外""还有"）−8、太长 −
2. 取最高分的分句，把**时间片段和地点片段抹成等长空格**
3. 去掉开头填充词（请/务必/于/在/把…）、去掉尾部的了/吧/呢

所以标题永远是原文里真实存在的动宾短语，用户一眼能对回去；不够好就直接改。

## 4. 字段规范

```ts
type Todo = {
  id: string;
  title: string;            // 动宾短语，≤42 字
  due: string | null;       // 'YYYY-MM-DDTHH:mm' 本地墙钟
  dueEnd: string | null;    // 时间段的结束
  dueText: string;          // 原文表述，如 "本周五上午10点前"
  precision: 'minute' | 'daypart' | 'day' | 'month' | 'year' | 'none';
  deadline: boolean;        // 是"截止"而不是"开始"
  place: string;
  people: string[];
  phones: string[];
  notes: string;            // 多条用 "；" 连接
  priority: 'high' | 'normal' | 'low';
  category: 'work' | 'study' | 'life' | 'health' | 'money' | 'social' | 'other';
  confidence: number;       // 0~1 启发式打分
  source: { text: string; marks: {field, start, end}[] };  // 原文出处 + 高亮区间
  done: boolean;
};
```

`precision` 很关键：只说了"周五"的待办，不该假装知道几点——导出 `.ics` 时会变成**全天事件**
（`DTSTART;VALUE=DATE`），而不是硬塞一个 00:00。

## 5. 界面结构

```
┌ topbar ── logo · 主题 · AI 设置 · GitHub ────────────────────┐
├ 左：粘贴区 ──────────┬ 右：结果区 ───────────────────────┤
│ textarea（撑满）      │ [提取结果] [我的待办]              │
│ 字数 / 引擎 / 抽取    │  批量条 / 卡片列表 / 空态           │
└──────────────────────┴───────────────────────────────────┘
```

- **卡片**是唯一的信息单位，草稿态和已保存态**共用同一个模板**（`<template id="tpl-card">`），
  靠 `data-mode` 切换显隐，避免两套 DOM 走两套事件。
- **原文出处**不弹浮层，直接在卡片底部展开（`◎` 按钮）——不打断视线，也不用算浮层定位。
- **分组**：已逾期 / 今天 / 明天 / 本周内 / 以后 / 没有时间 / 已完成。
- **输入即改**：卡片里所有字段都是原生 input，`input` 事件只更新内存不重渲染（避免光标丢失），
  `change` 事件（失焦）才重渲染列表（因为分组可能变了）。

这是时间相关逻辑最容易踩的坑。

## 7. 已知取舍

- **不生成、只剪裁**标题：牺牲一点自然度，换来"永远能在原文里找到依据"
- **一句一事件**：同一句里塞两件事（"开会并交材料"）会偏向拆成一条，靠备注兜住
- **续写词表是显式的**：`结束/散会/签到/出发/集合/开始…` 之外的收尾说法（比如"说到 5 点"）暂时识别不到
- **中文优先**：英文只做最低限度支持，因为规则引擎的成本几乎全在词表上
- **不用正则硬啃整句**：分层（归类→聚合→字段）比一条巨型正则好维护、好加用例
